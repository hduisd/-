# PROJECT_CONTEXT — Minecraft-мод «Віктор»

## Технічні дані
- Назва: Viktor / «Віктор», mod id `viktor`, пакет `com.viktor`
- Minecraft Java 1.21.1, NeoForge 21.1.172 (користувач грає на 21.1.257, сумісно), Java 21
- Збірка: ModDevGradle 2.0.78, Gradle 8.10.2 через GitHub Actions (wrapper відсутній)
- Робота: GitHub у браузері (Android-планшет)
- Оновлення: ZIP `viktor-starter.zip` (доповнення; один раз повний проєкт для ресинку) у корені репозиторію + Actions → «Unpack starter»,
  потім вручну Actions → «Build» (збірка після Unpack сама не запускається). Версія береться з `mod_version` у gradle.properties.

## Підтверджений стан (користувач повідомив, що працює)

  (купує 22 боби за 1 смарагд, продає 4 за 1), боби на полях сіл, фермери підбирають/садять/збирають боби.

## Важливі технічні рішення
- Рожеві моби (задум користувача: текстура як у звичайних, але рожева й гнила; мангові версії будуть пізніше): підкласи ванільних мобів (PinkZombie, PinkSkeleton, PinkCreeper)
  з власними EntityType; рендери (PinkZombieRenderer тощо) підкласи ванільних, перевизначають getTextureLocation. Текстури намальовані за ванільною UV-розкладкою
  (зомбі 128x128, скелет і кріпер 128x64). Поява: у biome pink_lands.json вони замінюють ванільних зомбі, скелета, кріпера. Дроп: рожева есенція.
  Щоб додати нового рожевого моба: клас, EntityType у ModEntities, атрибути й spawn у EntitySetup, рендер у ClientSetup, текстура, переклад, лут, запис у біомі, яйце.
- Рожева енергія (ідея користувача): нейтральний кристал + будь-який заряджений рожевий предмет на ритуальному столі → рожевий енергетичний кристал;
  заряджений рожевий предмет робиться з рожевого предмета + гниле манго на тому самому столі. Рожеві предмети (дропи рожевих мобів або нова руда) будуть пізніше.
- Ритуальний стіл без вікна: гравець тримає два предмети в руках і клацає по столу (RitualTableBlock, рецепти в класі Rituals.ALL, порядок рук неважливий).
  Щоб додати новий рожевий предмет: додати його в data/viktor/tags/item/pink_raw.json, додати рядок «сире → заряджене» у Rituals.ALL
  і додати заряджений варіант у pink_charged.json.
- Човни: 4 власні сутності (mango_boat, mango_chest_boat, olive_boat, olive_chest_boat) на ванільних класах Boat/ChestBoat; предмет ModBoatItem ставить човен
  як ванільний BoatItem; рендер ModBoatRenderer (підклас BoatRenderer) перевизначає getModelWithLocation, власні шари моделей `viktor:boat/<дерево>` і
  `viktor:chest_boat/<дерево>` (реєструє ClientSetup). Текстури: textures/entity/boat/*.png (256x128), chest_boat/*.png (256x256).
  Ванільний тип Boat.Type не розширювався, тому під час поломки від удару випадають дошки дуба (відома дрібна вада).
- Ланцюги висячих табличок: ділянки текстури (0..24,12..24) і V-ланцюги (28..76,12..24) мають прозорість; розкладка UV ванільної моделі.
- Таблички: ванільні класи StandingSignBlock/WallSignBlock/CeilingHangingSignBlock/WallHangingSignBlock з ModWoodTypes; блоки додаються до BlockEntityType.SIGN
  і HANGING_SIGN через BlockEntityTypeAddBlocksEvent (SignSetup). WoodType має імена 'viktor_mango' і 'viktor_olive' (без простору імен), тому текстури
  табличок у assets/minecraft/textures/entity/signs/viktor_*.png (128x64), .../signs/hanging/viktor_*.png, gui/hanging_signs/viktor_*.png (32x32).
  Настінні варіанти мають власні таблиці здобичі, що дають звичайну табличку.
- ПОГОДЖЕНО користувачем: залежність від TerraBlender для природної появи біома (зміна архітектури).
  Gradle: Modrinth maven (exclusiveContent), `implementation 'maven.modrinth:terrablender:6e8GCrLb'`. У mods.toml: modId terrablender, [4.1.0.0,).
- Біом `viktor:pink_lands` замінює PLAINS і FOREST у регіоні TerraBlender (вага 4); поверхня через SurfaceRuleManager (рожева трава/земля).
- Біом `viktor:baykivetska_land` («Байківецька земля»): другий регіон TerraBlender `viktor:baykivetska` (вага 4) замінює PLAINS, FOREST, SAVANNA;
  ванільна поверхня (трава з біомним кольором), оливкові дерева природно ростуть лише тут. Перевірка: `/locate biome viktor:baykivetska_land`,
  `/place feature viktor:green_olive_trees_natural`.
- Біом містить лише безпечні ванільні особливості (підмножина руд у канонічному порядку, spring_water, spring_lava) + власні, щоб не було конфлікту порядку особливостей між біомами.
- Перевірка в грі: `/locate biome viktor:pink_lands`; без світу: `/place feature viktor:mango_trees_natural`, `/fillbiome ~ ~ ~ ~20 ~20 ~20 viktor:pink_lands`.
- Моделі з прозорістю (рослини, скло, решітки) завжди з `render_type` (cutout/translucent).
- Торгівля через MerchantOffer/ItemCost (VillagerTrades.EmeraldForItems закритий для модів).
- Access transformer: META-INF/accesstransformer.cfg (Villager.WANTED_ITEMS), підключено в build.gradle.
- Боби на полях: feature `viktor:village_beans` (top_layer_modification) + biome modifier, біоми в тегу `viktor:village_biomes`.
- Мангове листя: властивість `fruit` 0-3 (немає, зелене, стигле, гниле), плід висить під листям (під ним має бути вільне місце), модель із плодом нижче блока.
- Годинник гниття манго: `ripe_age` 0-7 на випадкових тіках (p=0.15 за тік, 8 кроків ≈ 72000 тіків ≈ 3 доби при randomTickSpeed=3); заплановані тіки не використовуємо, бо вони ламали б оновлення відстані листя.
- Оливки: два дерева (green/black), листя з `fruit` 0-2; олива = ItemNameBlockItem на блок-саджанець (їжа + садіння). Дерева: зелене - forking_trunk_placer, чорне - bending_trunk_placer, обидва з random_spread_foliage_placer.
- Форма дерева: straight_trunk_placer (5-6) + fancy_foliage_placer (radius 3, height 3).
- Природна поява мангових дерев НЕ додана: за задумом лише в біомі «Рожеві землі» (біому ще немає).
- Мангові текстури 32x32 (реалістичні, згенеровані шумом і освітленням); боби в старому стилі 16x16.
- Таблички/висячі таблички/човен не зроблені (потрібні окремі сутності й текстури).

## Наступний крок
Запустити Build 0.14.0, перевірити яйця виклику та появу в Рожевих землях вночі, вигляд текстур, дроп есенції.
Далі: бобовий жук (перший власний моб), мангові версії ворожих істот, Бобофон.

## Правила роботи
- Оновлення: за замовчуванням ZIP лише з доповненнями (змінені файли), але з УСІМА змінами від останньої підтвердженої збірки (кумулятивно), щоб пропущений пакет не ламав збірку. Повний ZIP усього проєкту: лише коли репозиторій розійшовся з проєктом (разовий ресинк). Дрібні зміни: повний текст файлу для вставки.
- Перед віддачею перевіряти: унікальність оголошень, відповідність блоків/предметів/моделей/текстур/здобичі/перекладів.
- Нічого не позначати готовим без збірки й перевірки в грі.
